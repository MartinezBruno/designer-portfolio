## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/bot → /_actions/contact | Untrusted form data crosses into the Worker |
| Worker → challenges.cloudflare.com | Secret and token sent to siteverify |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-14 | Tampering | contactSchema | mitigate | astro/zod caps (name 100, email 254, message 5000, token 2048, honeypot 500), email pattern rejects CR/LF, enum service with catch('other'), enum locale |
| T-05-15 | Spoofing / abuse | bots posting the form | mitigate | Honeypot checked first (no network), then server-side Turnstile siteverify; empty token rejected; unit + e2e coverage |
| T-05-16 | Information disclosure | Action error responses | mitigate | Only `ActionError({ code: 'BAD_REQUEST', message: 'send_failed' })`; submitContact catches every throw; e2e asserts honeypot rejection body names no field |
| T-05-17 | Tampering (CSRF) | cross-origin POST | mitigate | Astro checkOrigin default (403, e2e asserted); requests without Origin are gated by Turnstile |
| T-05-18 | Information disclosure | secrets in bundles | mitigate | Secrets read only via `astro:env/server` (access secret); acceptance greps dist/client for the test secret and recipient |
| T-05-19 | Spoofing | Turnstile token replay | mitigate | Tokens single-use, 300 s (Cloudflare); client resets the widget after every attempt (05-05/05-06) |
| T-05-20 | Denial of service | flood of submissions | accept | No rate limiter in v1 (D-15, CONTEXT Deferred); Turnstile + honeypot cover local abuse; revisit at deploy |
| T-05-21 | Information disclosure | server logs | mitigate | logError details carry reasons and codes only, never name/email/message (unit-asserted) |
