<build_e2e_lock>
Same-wave dist/ isolation (checker revision). Plans in the same wave (W1: 08-01, 08-02, 08-03; W2: 08-04, 08-07) share one dist/, so a concurrent `pnpm build` can wipe it mid-run. Private ports do not fix this, and a per-plan Astro `--outDir` is not used ([Unverified] whether the Cloudflare adapter's dist/client + dist/server layout and `astro preview` in workerd honor a custom outDir).
Rule: every step that runs `pnpm build`, `astro preview`, Playwright, or inspect.mjs against the build holds an exclusive lock for the whole build-then-test span:
- Acquire: `mkdir -p tmp && mkdir tmp/build-e2e.lock && echo "08-03 $(date +%s)" > tmp/build-e2e.lock/owner`. mkdir is atomic; if it fails, another plan holds the lock. Do not proceed. Wait (re-check periodically with a background/Monitor until-loop, not a foreground sleep) and retry. tmp/ is gitignored.
- Hold it from the `pnpm build` through the last Playwright, preview, curl, or inspect step that reads dist/, including the task's automated verify command.
- Release: stop any preview server you started, then `rm -rf tmp/build-e2e.lock`. Release on failure too, before reporting.
- Stale lock: only remove someone else's lock if its owner plan's SUMMARY.md exists or no `playwright|astro (preview|build)` process is running (`pgrep -fl`). Record that in your SUMMARY.
Steps that do not touch dist/ (pnpm check, pnpm test, eslint, vitest) do not need the lock.
</build_e2e_lock>
