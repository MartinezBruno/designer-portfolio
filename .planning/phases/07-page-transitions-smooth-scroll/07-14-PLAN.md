<objective>
Give CollectionModule grids motion, per the user's Q5 answer at the 07-10 checkpoint ("CollectionModule grids get motion, not static"). Q5 offered "the same gentle drift per cell" as the alternative to static; this plan implements exactly that, reusing the card parallax engine (CSS `animation-timeline: view()`, zero JS) inside each cell's own clip frame.

Purpose: closes gap item 3 of 07-10 (MOTN-06), while keeping seam integrity (Phase 4 D-01, D-11a spirit) and the leak contract (MOTN-09).
Output: data flag, markup hooks, token override, unit + e2e tests, captures reviewed with the taste skill, UI-SPEC amended.

Discretion recorded [Proposed]: per-cell drift reuses the existing `[data-parallax-frame]`/`[data-parallax]` hooks, so (a) no new keyframes or timelines, (b) the 07-03 leak invariant counts cells automatically, and (c) from `sm` up every cell in a justified row has the same top and bottom, so their view timelines have identical progress and the row moves as one (this answers the UI-SPEC's "cells drifting independently read as jitter" concern). Travel uses the former detail-drift values from the UI-SPEC (`--px-overscan: 3%`, `--px-travel: 2.6%`), gentler than the card's 4%/3.5%.
</objective>
