# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this contract covers:** the motion layer on Home, Projects and project detail pages, in EN and ES:
- the three motion states (`on`, `reduced`, `off`) and what every element does in each (MOTN-07)
- the hero load sequence (D-03)
- the section reveal vocabulary and masked line-split headlines (MOTN-01, MOTN-02, D-01, D-02, D-04, D-05)
- the shared image hover and focus effect for project imagery links (MOTN-04, D-06..D-08)

- the header motion toggle: icon, name, states, hint, persistence, live switching (MOTN-08, D-14..D-18)

## Motion States `[CONTEXT D-14, D-15, D-17, D-18]`

`html[data-motion]` has three values. The blocking head gate resolves it before any stylesheet loads.

| State | Set when | Meaning |
|-------|----------|---------|
| `on` | JS runs, `matchMedia` exists, the OS has no reduced-motion preference, and storage does not hold `reduced` | Full motion |
| `reduced` | JS runs and `matchMedia` exists, and either the OS prefers reduced motion or storage holds `reduced` | Opacity fades only. No travel, scale, clip wipe, cursor, magnetic pull, card zoom or marquee travel |
| `off` | The markup default. It stays when JS is off or fails, or `matchMedia` is missing | Everything static and visible |

**Resolution order (inline gate, self-contained):** no `matchMedia` → `off`. OS reduce → `reduced`. Storage value strictly equal to `'reduced'` → `reduced`. Otherwise → `on`. A stored value is never interpolated into anything; any other value is ignored. Storage access is wrapped in `try/catch`; a throw falls back to the OS setting. `[CONTEXT D-17]`

**Storage:** key `motion-preference`, only value `'reduced'`. Pressing the toggle into reduced writes it. Releasing removes the key. Nothing stores `'on'`, so a stored value can never override the OS setting. `[Default; CONTEXT D-18]`

**CSS variants (names are the planner's call; these are proposed):** `motion-on:` (exists), `motion-reduced:` (new), and `motion-js:` matching `on` or `reduced`. `[Proposed]`

**Live switching (no reload):** the toggle and an OS change both update `data-motion` and dispatch one `motion:change` event on `document` with the new state. Phase 6 effects subscribe and adapt themselves. **The toggle must not call `lifecycle.unmount()`/`mount()` for the whole page**: `ContactForm`, `ServiceChips`, `EmbedFacade`, the tooltips and the marquee are registered there too, and a remount could reset a half-typed message or re-render Turnstile. `[Codebase: ContactForm.astro:228 lifecycle.register; Default]`

| On `motion:change` to… | Effect |
|------------------------|--------|
| `reduced` | Any running reveal jumps to its end state. Elements still waiting for a reveal switch to the fade path. The cursor layer is removed and its listeners aborted. Every magnetic offset returns to 0 instantly and its listeners are aborted. Hover zoom stops (CSS). The marquee stops (CSS, existing `motion-on` gate) |
| `on` | Already-revealed elements stay as they are. Waiting elements use the full path. GSAP loads if it has not yet. The cursor layer mounts and stays invisible until the next `pointermove`. Magnetic listeners attach. Nothing replays: the hero sequence and finished reveals never run again |

## Motion Tokens

Defined once in `global.css` (`@theme` for easings, `:root` custom properties for durations) and mirrored in a typed `src/lib/motion/tokens.ts` for GSAP, so CSS and JS never drift. `[Default; Taste: motion.md §3]`

| Token | CSS value | GSAP equivalent | Used for |
|-------|-----------|-----------------|----------|
| `--ease-reveal` | `cubic-bezier(0.22, 1, 0.36, 1)` | `power4.out` | Line rise, settle, hero, pill and dot changes |
| `--ease-travel` | `cubic-bezier(0.76, 0, 0.24, 1)` | `power3.inOut` | Shutter clip (a thing that travels while visible) |
| `--ease-soft` | `cubic-bezier(0.33, 1, 0.68, 1)` | `power2.out` | Image scale (reveal and hover), cursor follow, magnetic pull |
| `--t-press` | 140ms | 0.14 | Press feedback on pills |
| `--t-hover` | 180ms | 0.18 | Cursor dot scale and opacity |
| `--t-ui` | 240ms | 0.24 | "View" pill in, tooltip fade |
| `--t-fade` | 320ms | n/a (CSS) | Every opacity fade in `reduced` |
| `--t-settle` | 560ms | 0.56 | Settle reveal |
| `--t-line` | 640ms | 0.64 | Line rise (scroll) |
| `--t-shutter` | 720ms | 0.72 | Shutter clip (scroll) |
| `--t-hero` | 720ms | n/a (CSS) | Hero headline lines |

`[Inference]` The GSAP names map by the documented power scale (power2 = cubic, power3 = quart, power4 = quint). `CustomEase` is not loaded, so the curves are close equivalents, not exact copies. The executor checks them by eye in the GSAP ease visualizer. Eases never `bounce`, `elastic` or `back`, and no ease named `ease-in` appears anywhere in source, including comments, because `lint.mjs` flags it. `[Taste: no bounce or elastic; lint ease-in]`

**Staggers:**
- Inside one reveal batch: **70ms** between elements in DOM order, capped at the 5th element (the 6th and later share the 5th's delay, so no element waits more than 280ms).
- Between lines of one split heading: **80ms**.
- Cards and grid items in one batch: **90ms**.
`[Taste: staggered 60–90ms]`

**Trigger:** one shared `IntersectionObserver` with `rootMargin: '0px 0px -12% 0px'` and `threshold: 0`. Each element is unobserved after it reveals (D-02: once). Entries that arrive in the same callback form one batch. `[Taste: motion.md "Reveal on scroll"; CONTEXT D-02]`

**Duration ceiling:** no reveal, including its stagger, runs longer than 900ms. The hero ends by 960ms. `[Taste: section and hero reveals 500–900ms; CONTEXT D-03 "within about 1 s"]`

Animate `transform`, `opacity` and `clip-path` only. Name the properties (`transition-[clip-path]`, `transition-transform`), never `transition-all`. `will-change` only while a tween runs. `[Taste: motion.md §6; lint transition-all]`

## Reveal Contract (MOTN-01, MOTN-02)

### Visibility safety (D-05, Pitfall 8)

Every revealable element carries `data-reveal="lines" | "settle" | "shutter"`. Its hidden state exists only under `html[data-motion]` = `on` or `reduced`. A failsafe makes sure nothing stays hidden if the script fails:

| Element state | Who sets it | CSS (under `on`/`reduced`) |
|---------------|-------------|----------------------------|
| plain (`[data-reveal]` with no state attribute) | markup | Hidden start state, **plus** `animation: reveal-failsafe 1ms linear 1500ms forwards` whose keyframe ends at the visible state. If no script arms the element within 1.5s, CSS shows it |
| `[data-reveal-armed]` | the reveal effect at mount | Hidden start state, no failsafe. The observer owns it |
| `[data-revealed]` | the reveal effect on intersection | End state (`opacity: 1`, `transform: none`, `clip-path: inset(0)`) with the transition for the current state |

- **Late mount rule:** if the reveal effect mounts after 1500ms (`performance.now()`), elements already in the viewport are set straight to `data-revealed` with no transition, because the failsafe has already shown them. Only elements below the viewport are armed. This prevents a visible-to-hidden flash on slow connections. `[Default]`
- In `off` none of these selectors match, so everything is visible. `[CONTEXT D-05]`
- A CSS animation overrides inline styles, so arming must remove the failsafe before GSAP writes any inline style. That is why the armed state exists. `[Inference: CSS cascade, animations beat inline declarations; checked by the e2e "JS fails after gate" test below]`
- Never put `data-reveal` and `data-magnetic` on the same element. Never put `data-reveal` on an element that the hover effect transforms. Each property belongs to exactly one layer (see the card layering below). `[Default]`

### The vocabulary `[Default inside CONTEXT "Claude's Discretion"; Taste: vary the manner with the content, never one preset everywhere]`

Three reveals, each matched to a kind of content. There is no global fade-up.

| Name | For | `on` | `reduced` | `off` |
|------|-----|------|-----------|-------|
| **Line rise** (`lines`) | Section headings (h2), the Projects h1, the detail h1, the contact band h2, the Next-project h2 | SplitText `type: 'lines'`, `mask: 'lines'`. Each line goes from `yPercent: 110` to 0, `--t-line`, `power4.out`, 80ms between lines. The heading itself stays at opacity 1. Revert the split `onComplete` | Whole heading opacity 0 → 1, `--t-fade`. No split at all | static |
| **Settle** (`settle`) | Paragraphs, metadata rows, link rows, card text, list items, form | `opacity: 0; translateY(20px)` → visible, `--t-settle`, `--ease-reveal` | opacity 0 → 1, `--t-fade` | static |
| **Shutter** (`shutter`) | Project covers (cards, teaser) | The cover frame's `clip-path: inset(0 0 100% 0)` → `inset(0)` over `--t-shutter` with `--ease-travel`. The `<picture>` inside scales 1.08 → 1 over 900ms with `--ease-soft`. The image opens from the bottom edge while settling | Cover frame opacity 0 → 1, `--t-fade` | static |

**SplitText contract (D-01):**
- `tag: 'span'` so the heading still holds only phrasing content. The line masks get `padding-block: 0.1em; margin-block: -0.1em` (see Spacing).
- Accessible text: a heading with plain text uses `aria: 'auto'`. SplitText puts an `aria-label` with the full text on the heading and `aria-hidden` on the line spans. A heading that contains a `lang` span (detail h1 when `titleLang` is set) uses `aria: 'none'`, so the `lang` span keeps its language. `[Documented: gsap.com SplitText "aria"]`
- The split runs at reveal time, not at mount, so headings below the fold are never split before they are needed. `autoSplit: true` with the tween returned from `onSplit` handles a font swap or a resize mid-reveal.
- Long Spanish headings simply produce more lines. Nothing is authored per locale.
- Headings that wrap a link (card titles, the Next-project h3) are **not** split. They settle. A split would strip the link's semantics under `aria: 'auto'`. `[Documented: "Nested elements such as links lose their semantics"]`

### Hero load sequence (D-03) `[CONTEXT D-03; Taste: hero load sequence, stagger at most four things]`

Pure CSS keyframes under `html[data-motion="on"]`, so the sequence starts with the first frame and finishes even if every script fails. No preloader, no blank frame, no JS-dependent hidden state.

| # | Element | From → to | Delay | Duration | Ease |
|---|---------|-----------|-------|----------|------|
| 1 | Headline line 1 ("Hi, I'm" / "Hola, soy") | inner span `translateY(110%)` → 0 inside its line mask | 0ms | 720ms | `--ease-reveal` |
| 1 | Headline line 2 ("Martina.") | same | 90ms | 720ms | `--ease-reveal` |
| 2 | Portrait | `clip-path: inset(100% 0 0 0)` → `inset(0)` on the `<picture>`; `<img>` scale 1.08 → 1 | 120ms | clip 840ms (`--ease-travel`), scale 840ms (`--ease-soft`) | as listed |
| 3 | Lead paragraph | `opacity: 0; translateY(16px)` → visible | 200ms | 560ms | `--ease-reveal` |
| 4 | CTA row (pill + availability badge) | `opacity: 0; translateY(16px)` → visible | 280ms | 560ms | `--ease-reveal` |

Ends at 960ms. The headline's two lines are one gesture, so four things are staggered.

- **Line masks:** each existing `<span class="block">` line in the h1 becomes the mask (`overflow: clip`, the 0.1em padding pair), with one inner span that moves. The authored two lines stay the source of truth. If a line wraps on a narrow phone, its wrapped lines move together inside one mask. `[Codebase: Hero.astro authored lines]`
- **No replay:** when the sequence ends, the hero section gets `data-hero-played` (set on `animationend`). The keyframe selectors exclude it, so toggling `reduced` → `on` later never replays the hero. Without JS the attribute is never set, which is harmless: the gate only flips on load.
- **`reduced`:** the hero is static. No fade either: it is the first thing on screen, and fading it adds nothing for someone who asked for less motion. `[Default]`
- **`off`:** static.
- **LCP gate:** median LCP with `on` must be within **100ms** of median LCP with `reduced` on `/` and `/es/` at 1440×900 and 390×844 (5 runs each, Playwright + `PerformanceObserver('largest-contentful-paint')`, preview build). `[Inference]` Chrome may not report a fully clipped element as painted until it is partly visible. ## Cursor Follower (MOTN-03, D-09..D-11, D-13)

**Mount conditions (all required):** `matchMedia('(hover: hover) and (pointer: fine)').matches`, `html[data-motion="on"]`, and not `forced-colors: active`. The effect listens to all three media queries and to `motion:change`, and mounts or unmounts live. On touch, `reduced`, `off` or forced colours, the follower element is never created. `[CONTEXT D-13; Research: Pitfall 9]`

**Markup:** one layer created by the effect and appended to `<body>`: `div[aria-hidden="true"]`, `fixed inset-0 z-50 pointer-events-none overflow-clip`. The clip guarantees the follower can never cause horizontal scroll. Inside it are the dot and the pill. Neither is focusable, and neither has text in the accessibility tree. The native cursor is never hidden: no `cursor: none` anywhere. `[CONTEXT D-09, D-11]`

| Part | Rest | Over a link or button | Over project imagery (`[data-cursor="view"]`) |
|------|------|-----------------------|-----------------------------------------------|
| Dot | 12px (`size-3`) `rounded-full bg-accent`, centred on the pointer, opacity 1 | `scale(2)` (24px) and opacity 0.35, `--t-hover`, `--ease-reveal` | opacity 0, `--t-press` |
| "View" pill | hidden: opacity 0, `scale(0.6)` | hidden | `h-8 px-4 rounded-full bg-accent text-accent-ink text-sm font-semibold`, label `cursor.view`, centred on the pointer. In: opacity 1, `scale(1)`, `--t-ui`, `--ease-reveal`. Out: 170ms |

- **Follow:** `gsap.quickTo` on `x` and `y`, duration 0.25s, `power2.out`. That gives a slight lag behind the native pointer. One `pointermove` listener on `document`, passive. Layout is never read in the move handler.
- **What counts:** "link or button" means `a[href]`, `button`, `[role="button"]`, `summary` and `label[for]`. "Project imagery" means the `article.group/card` elements in ProjectCard and NextProjectTeaser, which get `data-cursor="view"`. Delegated `pointerover`/`pointerout` on `document`.
- **Hidden (opacity 0, 140ms):** until the first `pointermove` (so no dot sits in the top-left corner), when the pointer leaves the window, on `blur`, over `input`, `textarea` and `select` (the I-beam needs no company), and over any `iframe` (the embed and Turnstile swallow pointer events). `[Research: Pitfall 9]`
- Under the dot the native cursor still points. The dot never covers text at rest: it is centred on the pointer tip, and the native arrow sits above it.
- **Cleanup:** one `AbortController` for every listener, `quickTo` tweens killed, the layer removed. It is registered through `lifecycle` like the marquee. `[Codebase: marquee.ts pattern; CONTEXT SC5]`

## Magnetic Targets (MOTN-03, D-12, D-13)

**Targets (`data-magnetic`):**
- every `primaryButton` instance: the hero CTA, the 404 CTA, the detail contact band button, the contact submit (all states), the no-JS "Email me" (moot: it only renders without JS)
- the two stand-alone arrow links that D-12 names: "See all projects" (Home) and "View on Behance" (detail intro)
- every `IconLink` social icon (footer and contact section)

**Not magnetic:** nav links, the wordmark, language links, the motion toggle, inline links inside paragraphs and text modules, the email links, "Ask about this", "Previous", `inkButton` ("Send another message", the embed load button), the marquee pause, chips and form fields. `[CONTEXT D-12]`. "See all projects" and "View on Behance" are text links by style, but they stand alone on their own row as a section's way out, which is why D-12 lists them. Links inside running text stay still.

**Hit area stays put (Pitfall 9):** the element that owns the hit area and the focus outline never moves. Only an inner face moves.
- Pills: the classes split into a shell (`a`/`button`: `inline-flex h-12 rounded-full`, the focus outline, no fill) and a face (`span[data-magnetic-face]`: fill, padding, label, icon, hover fill). `button-classes.ts` exports both, so the hero, band, 404 and submit stay identical at rest. `[Research: Pitfall 9; Upstream: 05-UI-SPEC shared classes]`
- Text links and icon links: the inner content (text + icon) is wrapped in `span[data-magnetic-face]`. The underline lives on the text, so it travels with the face.
- Verification: at rest the rendered pixels match the Phase 5 build (screenshot diff at 1440 and 390), and the `class` sets of the shells plus faces carry the same utilities as before.

| Parameter | Value |
|-----------|-------|
| Activation zone | the shell's box plus 24px on every side |
| Pull | face offset = (pointer − shell centre) × 0.3 |
| Cap | 8px for pills, 6px for text and icon links (clamped on each axis) |
| Follow | `quickTo` x/y, 0.3s, `power2.out` |
| Release | back to 0 over 400ms, `power2.out`. No overshoot, no elastic |
| Press (`on` only) | the pill face scales to 0.97 on `:active`, `--t-press`, `--ease-reveal` (CSS, `motion-on:active:scale-[0.97]`) |
| Measure | the shell rect is read on `pointerenter` and on `resize`, never inside the move handler `[Research: ARCHITECTURE Pattern 5 rule 7]` |
| Keyboard | no movement on focus. The focus outline is on the stationary shell |
| `reduced` / `off` / touch | no listeners, face at 0. Press scale is off too |

Never combine magnetic with a reveal on the same element. The reveal goes on a wrapper (`<p>`, `<li>` or the CTA row). `[Default]`

## Motion Toggle (MOTN-08, D-14..D-18)

**Placement:** in `SiteHeader`, on every page, as the last item of the header in DOM order: wordmark → nav → languages → **toggle**.
- **From `sm` (one 64px row):** directly right of the language switcher, `gap-2` (8px). Visual order matches DOM order.
- **Below `sm` (two rows):** the toggle sits at the right end of **row 1**, opposite the wordmark. Row 2 keeps nav + languages unchanged. Row 2 cannot hold it: at 320px the row is 288px wide and nav (ES 154px) + languages (101px) + its gap (8px) already use 263px, so a 44px toggle plus its 8px gap would need 315px. `[Verified: Playwright on dist/client at 320/360/390, EN nav 133px, ES nav 154px, languages 101px, row 288/328/358px, 2026-10-29]`
- **Focus order below `sm`:** wordmark → Projects → Contact → EN → ES → toggle. The toggle is last in DOM order at every width, so the tab sequence is the same everywhere. Below `sm` focus moves from ES up to row 1's right end. `[Default]` I judge this acceptable under WCAG 2.4.3, because the sequence is consistent and predictable, but it is the one place where visual order and tab order differ. It is listed under Open Questions. `[Inference]`
- The header height does not change (88px below `sm`, 64px from `sm`). `[Verified: header 89px at 320–390 today; Codebase: sm:h-16]`

**Element:** `<button type="button" data-motion-toggle aria-pressed="…">` with the two icons inside, `inline-flex min-h-11 min-w-11 items-center justify-center text-ink`, `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent`, `hover:text-ink-muted motion-safe:transition-colors motion-safe:duration-150` (the same hover as `IconLink`).

**No JS:** the button is `hidden` and shown by `motion-js:inline-flex`. Because the gate runs before the stylesheet, the button is there from the first paint when JS runs, so nothing shifts. Without JS, or without `matchMedia`, the button does not render, and it can do nothing anyway. `[CONTEXT D-05, D-17]`

| State | `aria-pressed` | Disabled | Icon | Visible tooltip (hover/focus) | `aria-describedby` |
|-------|----------------|----------|------|--------------------------------|--------------------|
| Full motion | `false` | no | `sparkles-2`, ink | `motion.toggle` ("Reduce motion") | none |
| Reduced by the visitor | `true` | no | `sparkles-2-off`, ink | `motion.toggle` | none |
| Reduced by the OS | `true` | `aria-disabled="true"` (stays focusable, ignores clicks) | `sparkles-2-off`, `text-ink-muted` | `motion.osLocked` ("Your device settings already reduce motion.") | the hint's sr-only node |

- **Name:** `motion.toggle`, the same in every state. State lives in `aria-pressed`, so a screen reader hears "Reduce motion, toggle button, pressed / not pressed". The name starts with the tooltip text (Label in Name). `[Default; WAI-ARIA toggle button pattern]`
- **OS lock:** D-18 says the toggle can only reduce. When the OS asks for reduced motion the button shows pressed, uses `aria-disabled` (not `disabled`, so keyboard and screen-reader users can still reach it and hear the hint), and does nothing on click. A stored value is not changed by the lock. If the OS setting is later turned off, the button unlocks and shows the stored choice. `[CONTEXT D-18]`
- **Tooltip:** the Tools tooltip pattern, placed below the button and anchored to its right edge (`right-0 top-full pt-2`), `aria-hidden="true"`, pill `bg-ink text-surface rounded-lg px-2 py-1 text-sm font-semibold`, `w-max max-w-64` so the long Spanish hint wraps inside 256px instead of overflowing a 320px screen. It shows on `hover` and `focus-visible`, fades over `--t-ui` in `on` and appears instantly otherwise. `Esc` hides it while focus stays. `[Upstream: ToolsRow tooltip pattern; Default]`
- **Activation:** click, Enter and Space (native button). Pressing toggles `data-motion` between `on` and `reduced`, writes or removes the storage key, dispatches `motion:change`, and flips `aria-pressed`. There is no reload and no live-region message: `aria-pressed` is announced by itself.
- **Persistence:** later pages read the key in the blocking gate, so they never flash motion. `[CONTEXT D-17]`
