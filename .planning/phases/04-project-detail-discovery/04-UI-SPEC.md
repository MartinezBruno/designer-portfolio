# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this contract covers:** the visitor-facing parts of Phase 4, in EN and ES:
- the project detail page at `/projects/<slug>/` and `/es/projects/<slug>/` (PROJ-02, PROJ-03), built from these parts:
  - the intro band: title, summary, metadata and "View on Behance"
  - the module stack: `ImageModule`, `TextModule`, `MediaCollectionModule`, the `EmbedModule` facade, and the fallback for unknown modules
  - the contact band
  - the next-project teaser plus the previous link
- the record that discovery (PROJ-04..07) is N/A, so the Projects page gets **no** filter or search UI

**Out of scope:**
- motion on the detail page (D-04; Phases 6–7)
- filters and search (D-16)
- the per-project `canvasBg` override (deferred)
- drafting the 154 module alts (deferred; they show up as `TODO(martina)` in the sync checklist)
- the sync internals. Only their developer-facing copy appears here.

**Inheritance:** `01-UI-SPEC.md`, `02-UI-SPEC.md` and `03-UI-SPEC.md` (all approved) still apply where this document is silent. That covers tokens, the accent focus ring, 44px touch targets, the "no content hidden by `data-motion`" rule, the copy rules, the rule of no string literals in components, the stretched-link card pattern and the 32-character title cap.

**Provenance labels:**
- `[CONTEXT D-nn]`: a locked decision in `04-CONTEXT.md`.
- `[Upstream]`: decided in earlier UI-SPECs, PROJECT/CLAUDE.md, AGENTS.md or `research/STACK.md`. The source is named.
- `[Codebase]`: read from `src/` on 2026-10-17.
- `[Verified]`: measured or computed on 2026-10-17. The method is named.
- `[Default]`: my choice, inside a CONTEXT "Claude's Discretion" area.
- `[Inference]` / `[Assumption]`: not yet measured or confirmed. Each one says how it will be checked.

**Taste skill:** CLAUDE.md requires `taste-skill` for this work. The skill's special case "A component or a single section, not a page" applies in spirit. The detail page is a new route, but it sits inside an established design with locked tokens and type, so no direction is drawn. The surrounding design is matched and the house rules and laws are applied. Decisions taken from the skill are tagged `[Taste: <rule>]`. The result must pass `lint.mjs` and `inspect.mjs`, and the screenshots must be reviewed (see Verification).

**Visual hierarchy (detail page):**
1. **Focal point: Martina's work.** The seamless image stack starts right under the intro band and runs up to 1400px wide, wider than any text on the site. `[CONTEXT D-01, D-06; Taste: one dominant image beats six small ones; large things run to the edges]`
2. **Second: the project title** (36px on phones, 48px from `sm`), the largest type on the page.
3. **Third: the closing pair.** The contact band is the page's only accent button. The next-project teaser has a large cover and a large title.
4. Metadata, summary and links stay small and quiet.

## Spacing Scale

Same 4px-based Tailwind scale as Phases 1–3. No new spacing tokens.

| Token | Value | Tailwind | Usage (Phase 4) |
|-------|-------|----------|-----------------|
| xs | 4px | `1` | Gap between a meta `<dt>` and its `<dd>` (`gap-1`) |
| sm | 8px | `2` | Tool icon to name (`gap-2`); row gap of the tools list (`gap-y-2`); external link text to arrow (`gap-2`); "Previous" arrow to text (`gap-2`) |
| md | 16px | `4` | Gap between tools (`gap-x-4`); facade inner stack (`gap-4`); cover to title in the next tile (`gap-4`); text-module side padding on phones (`px-4`) |
| lg | 24px | `6` | h1 to summary (`gap-6`); meta row wrap gap (`gap-y-6`); facade inner padding on phones (`p-6`); contact band heading group to button (`gap-6`); teaser grid column gap (`md:gap-x-6`) |
| xl | 32px | `8` | Title group to meta row (`gap-8`); facade inner padding from `sm` (`sm:p-8`); teaser grid row gap on phones (`gap-y-8`) |
| 2xl | 48px | `12` | Gap between meta groups from `md` (`md:gap-x-12`); intro band bottom padding (`pb-12`); vertical padding around text modules, the facade and the unknown-module note (`py-12`) |
| 3xl | 64px | `16` | Intro band top padding (`pt-16`); contact band and teaser vertical padding (`py-16`) |

Exceptions:
- **Zero gap inside the image stack and inside collection grids.** Images touch, edge to edge and top to bottom. `[CONTEXT D-01: "do not add card frames, gaps or rounded corners between images"]`
- **The 1400px stack width** (`max-w-[1400px]`) is wider than the site's `max-w-6xl` (1152px) content column, on purpose. The stack has **no side padding** at any width. Below 1400px the images run the full viewport width. `[CONTEXT D-01, D-06; Taste: large things run to the edges]`
- **Touch targets:** every link and button is at least 44px tall (`min-h-11`), or 48px for the facade button (`h-12`, the same as `ButtonLink`). Links inside sanitized text-module prose are inline links in a sentence. They fall under the WCAG 2.5.8 inline exception and are not padded. `[Upstream: 01-UI-SPEC]`
- Text column: `mx-auto max-w-6xl px-4 sm:px-6 lg:px-8`, the same as every other section `[Codebase]`. Text modules narrow further to `max-w-[65ch]` (see Module stack). `[Taste: text 45–75 characters per line]`
- **Known, not changed here:** section gaps stay at 64px. Taste asks for 120–220px. Retuning that is site-wide polish, already recorded as Phase 3 Open Question 4.

## Typography

Phase 4 adds **one** size token (`text-4xl`, 36px), used only by the detail h1 and the next-project title below their breakpoint. Weights stay **400 and 600**.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Label / meta | 14px (`text-sm`) | 400 | 1.4 | Inter |
| Body | 16px (`text-base`) | 400 for summary, prose, notes and meta values; 600 for link actions ("View on Behance", "Previous", fallbacks) | 1.5 | Inter |
| Heading | 24px (`text-2xl`) | 600 | 1.3 | Bricolage Grotesque |
| Display | 36px (`text-4xl`) phones, 48px (`text-5xl`) from the breakpoint | 600 | 1.1 | Bricolage Grotesque |

At any one viewport width, a detail page shows **4 sizes** (14, 16, 24 and either 36 or 48), which is under the taste ceiling of 5. `[Taste: five sizes on a page is the ceiling]`

### Why 36px on phones `[Verified: Chromium via Playwright, Bricolage Grotesque variable woff2 from node_modules, weight 600, tracking -0.025em, line-height 1.1, 2026-10-17]`

| Width (content box) | 48px: titles over 2 lines | 36px: titles over 2 lines |
|---------------------|---------------------------|---------------------------|
| 288px (320 viewport) | "Cabrera's Motos social posts" (3), "Posts para Cabrera's Motos" (3), "Need something like this?" (3) | none of the 7 EN + 7 ES titles, Behance fallbacks or the band/teaser headings |
| 358px (390 viewport) | the same two titles (3 lines each) | none |
| 446px | none | none |

48px needs at least about 446px of content width for the longest real title, and `sm` (640px viewport, 592px content) clears that. The two-line rule `[Taste: headlines two lines or fewer at every width]` therefore holds with `text-4xl sm:text-5xl` and fails with `text-5xl` alone.

Caveat `[Verified, same run]`: an artificial 32-character worst case ("Wwwwwwww Wwwwwww Wwwwww Wwwwwww") wraps to 4 lines even at 36px/288px, so the 32-character cap does not by itself guarantee two lines. The gate is the e2e line-count check on the **real** titles (see Accessibility Contract), plus inspect's `headline-lines` at 390.

| "Previous" link | `<a>` | `text-base font-semibold`, see Interaction states |

Rules:
- **Heading outline:** h1 (project title) → h2 "Need something like this?" → h2 "Next project" → h3 (next title) → h2 footer "Let's talk". The modules contribute **no headings**. The sanitizer turns any `h1`–`h6` in Behance text into `<p><strong>…</strong></p>`, which protects the outline. `[Default]` (No current text module contains a heading `[Verified: 4 TextModules in snapshot.json read 2026-10-17]`.)
- **Fallback titles keep their original language:** `<span lang={titleLang}>` inside the h1, the next h3, the "Previous" link and the `<title>` source, exactly as on cards. `[Upstream: 03-UI-SPEC]` (All 7 projects currently have title overrides `[Verified: project-overrides.json]`, so no fallback renders today.)
- Text-module typography is **always** the site's. Behance `font-family`, `font-size` and `color` are stripped at sync. The 12–22px, Arial/Garamond and `#ffffff`/`#f8f5c2` values in the snapshot never reach the page. `[CONTEXT D-02; Verified: snapshot TextModule HTML]`
- No `truncate`, `line-clamp` or fixed text heights. No uppercase transforms or letter-spaced labels. The visible `<dt>` labels are sentence case, 14px, not tracked. `[Taste: no tiny uppercase letter-spaced labels]`
- **No date anywhere** on the page, in metadata, alt text or SEO copy. `[CONTEXT D-12; user 2026-10-17]`

## Layout & Component Contract

### Data boundary `[CONTEXT code_context; Upstream: 03 D-23 / DATA-06]`

- Pages call the query layer (`src/lib/content/queries.ts`) only. A new `getProjectDetail(locale, slug)` (or `getStaticPaths` data) returns a plain, already-localized `ProjectDetailView`. Components never import the snapshot, the overrides or the Behance adapter.
- `ProjectDetailView` (resolved UI type, no optional properties):
  - `slug`, `title`, `titleLang`, `summary | null`, `category | null` (the localized service title)
  - `tools: readonly { name: string; icon: ToolIconKey | null }[]`, in source order. `icon` is `null` when the Behance tool title matches no `tools.json` name
  - `behanceUrl`, `cover: ImageMetadata` (for OG and the teaser)
  - `modules: readonly ModuleView[]`
  - `next: TeaserView | null`, `previous: TeaserView | null`
  - `seo` data
- `ModuleView` is a discriminated union:
  - `image`: `ImageMetadata`, `alt`, `fullBleed`, `caption | null`, `eager`
  - `text`: sanitized `html`, `lang | null`
  - `collection`: `rows: readonly (readonly { image, alt, ratio }[])[]`
  - `embed`: `src` (allowlisted), `provider`, `iframeTitle`
  - `unknown`: no payload; it uses `behanceUrl`
- The renderer is a `ProjectModule.astro` dispatcher plus one small component per kind: `ImageModule.astro`, `TextModule.astro`, `CollectionModule.astro`, `EmbedFacade.astro`, `UnknownModule.astro`. Pure helpers (`collectionRows`, alt numbering, the embed allowlist, next/previous) live in `src/lib/projects/` and are unit-tested. `[CONTEXT Claude's Discretion; Upstream: AGENTS.md small components]`

### Page frame

Routes: `src/pages/projects/[slug].astro` and `src/pages/es/projects/[slug].astro`. They are thin, use `getStaticPaths` from the query layer (visible projects only; hidden projects get no page), and render `<ProjectDetailView locale slug />` inside `BaseLayout kind='page'`. The language toggle swaps `/projects/<slug>/` ↔ `/es/projects/<slug>/`, since the slug is the same in both locales. `[CONTEXT D-08 (Phase 3), D-13]`

DOM order inside `<main>`:

```
<article aria-labelledby="project-title">
  <header>  intro band  </header>
  <div>     module stack (max-w-[1400px], zero gaps)  </div>
</article>
<section aria-labelledby="project-cta-title">   contact band (bg-surface-alt)  </section>
<section aria-labelledby="next-project-title">  next-project teaser             </section>   ← omitted when next is null
(footer from BaseLayout)
```

The cover is **not** repeated as a hero. `[CONTEXT D-11]`

### Intro band `[CONTEXT D-11, D-12]`

```
<header class="mx-auto flex max-w-6xl flex-col gap-8 px-4 pt-16 pb-12 sm:px-6 lg:px-8">
  <div class="flex flex-col gap-6">
    <h1 id="project-title" …>{title | <span lang>title</span>}</h1>
    {summary && <p …>{summary}</p>}
  </div>
  <div class="flex flex-col gap-6 md:flex-row md:items-end md:justify-between">
    <dl class="flex flex-col gap-6 md:flex-row md:gap-x-12">
      {category && <div class="flex flex-col gap-1"><dt>Category</dt><dd>{category}</dd></div>}
      {tools.length > 0 && <div class="flex flex-col gap-1"><dt>Tools</dt>
        <dd><ul class="flex flex-wrap gap-x-4 gap-y-2">
          <li class="inline-flex items-center gap-2">{icon && <ToolIcon name={icon} size="sm"/>}{name}</li> …
        </ul></dd></div>}
    </dl>
    <p><ExternalTextLink href={behanceUrl}>{View on Behance}</ExternalTextLink></p>
  </div>
</header>
```

- **The `<dt>` labels are visible** here, unlike on cards (where they are sr-only). The page has room, and labelled values read better than an unlabelled row. `[Default]`
- Missing category: the group is omitted. No tools: the group is omitted. Missing summary: the `<p>` is omitted. No placeholders and no reserved space. `[Upstream: 03 D-14, D-22]`
- An unmatched tool shows its name with no icon and no placeholder icon. `[CONTEXT D-12]`
- No chips, pills, boxes or rules. `[Taste: no pill badges; no thin rules]`
- No date. `[CONTEXT D-12]`

### External text link (new shared component `ExternalTextLink.astro`)

It is used for "View on Behance", the facade fallback and the unknown-module link. It is the text form of the `IconLink` new-tab pattern, extracted so the classes are not duplicated. `[Upstream: AGENTS.md "no duplicar clases"]`
- `<a href target="_blank" rel="noopener noreferrer" class="text-ink decoration-accent focus-visible:outline-accent inline-flex min-h-11 items-center gap-2 text-base font-semibold decoration-2 underline-offset-4 hover:underline focus-visible:underline focus-visible:outline-2 focus-visible:outline-offset-2">`
- Content: `<slot/>` + `<span class="sr-only">{t('a11y.newTab')}</span>` + `arrow-up-right` `size-4` `aria-hidden`.
- Accessible name, e.g. "View on Behance (opens in a new tab)".

### Module stack

Wrapper: `<div class="mx-auto flex w-full max-w-[1400px] flex-col">`. It has no gap and no padding. Children render in Behance order.

**Language:** only **text** content is in the original language. `lang={contentLang}` goes on each **TextModule root** (and on a caption, if one ever exists). It is omitted when `contentLang` equals the page locale. Images, the facade and the unknown note carry page-locale text (alt, iframe title, UI copy), so they do **not** sit inside a `lang={contentLang}` wrapper. Wrapping the whole stack would mislabel the English alt text as Spanish. `[CONTEXT D-11 intent; Inference: WCAG 3.1.2 requires each part's language to be correct]`

Today's module mix `[Verified: snapshot.json, 2026-10-17]`: 127 ImageModule, 9 MediaCollectionModule (2–5 components each, 27 images), 4 TextModule, 1 EmbedModule, across 7 projects. Per project: Cabrera's 6 images; PuroV 22 images + 1 text; Reciclick 17 images; Portfolio-web 10 images + 1 embed; Sistema-visual 1 image + 1 text; InstaBlogs 58 images + 9 collections + 1 text; Mart 13 images + 1 text.

#### ImageModule `[CONTEXT D-01, D-05, D-06, D-09]`

- `fullBleed: 1` (every image module today): `<Picture src alt formats={['avif','webp']} widths={widthsUpTo1400} sizes="(min-width: 1400px) 1400px, 100vw" width height class="block h-auto w-full bg-surface-alt" loading decoding="async" />`.
  - `widthsUpTo1400` = `[640, 960, 1400]` filtered to widths ≤ the stored image width. There is no upscaling.
  - `block` removes the inline-image baseline gap, so the stack is truly seamless.
  - Intrinsic `width`/`height` come from the stored file, so there is no layout shift.
  - Square corners, no border, no shadow, no rounding. `[Taste: media square; no shadows]`
- `fullBleed: 0` (none today): the same `<Picture>` inside `mx-auto w-full max-w-6xl px-4 sm:px-6 lg:px-8`, still with no vertical gap. `[Default: honours Behance's padded layout]`
- **Loading:** the first image in the stack (module index 0, or the first image of the first collection) is `loading="eager" fetchpriority="high"`, because it is the LCP candidate directly under the intro band. Every other image is `loading="lazy"`.
- **Caption** (empty on every module today): if one is non-empty, the image is wrapped in `<figure>`, followed by `<figcaption lang={contentLang?} class="mx-auto max-w-6xl px-4 py-2 text-sm text-ink-muted sm:px-6 lg:px-8">`. `[Default]`
- **Alt:** `moduleAlt[moduleId][locale]` override, or else `interpolate(t('detail.imageAlt'), { title, n, total })`.
  - `n` and `total` count every image on the page in DOM order, image modules and collection components alike.
  - Example: "Reciclick website — image 3 of 17".
  - Behance `altText` is **never** used. `[CONTEXT D-09; Upstream: 03 D-15]`

#### TextModule `[CONTEXT D-02]`

- **The sanitizer runs at sync time** (`sanitize-html`, script-only). The snapshot stores the clean HTML, and the component renders it with `set:html`. That makes this the **second and only other** `set:html` in `src/`, allowed **only** for sanitized module HTML. A unit test asserts the sanitizer output for the 4 real modules and for XSS fixtures.
- **Allowlist (UI contract):**
  - tags: `p`, `div`, `br`, `a`, `strong`, `b`, `em`, `i`, `span` (with no attributes)
  - attributes: `a[href]` (schemes `http`, `https`, `mailto` only)
  - styles: `text-align: left|right|center|justify` only, on `div`/`p`

#### MediaCollectionModule: the collection grid `[CONTEXT D-10]`

- **Below `sm` (under 640px):** each component stacks full width, `block w-full h-auto`, with zero gap, the same as the image stack. Columns of 130px on a phone would shrink her compositions to illegibility. `[Default; Taste: a phone layout that is its own composition]`
- **From `sm`:** components are split into rows by the pure function `collectionRows(components)` (unit-tested):
  - 1–3 components: one row
  - 4: 2 + 2
  - 5: 3 + 2
  - 6: 3 + 3
  - in general, rows of 3, and when the remainder is 1 the last two rows become 2 + 2
  - So columns are **2 or 3, never 1 or 4+**.
- **Each row is an equal-height justified row with no cropping:**
  - row: `<div class="flex flex-col sm:flex-row">`
  - item: `<div class="min-w-0 sm:basis-0 sm:grow-(--ar)" style={{ '--ar': ratio }}>`, where `ratio = width / height` (4 decimals)
  - image: `block h-auto w-full`
  - Flex-grow proportional to the aspect ratio, with basis 0 and no gaps, gives every item in a row the same rendered height (height = row width ÷ Σratio). Nothing is cropped, and it keeps her portrait/landscape mixes intact. The real rows mix ratios from 0.54 to 1.71. `[Verified: arithmetic; snapshot component dimensions read 2026-10-17]` `[Inference]` Confirm that Tailwind compiles `grow-(--ar)` to `flex-grow: var(--ar)` by grepping the built CSS. If it does not, use the arbitrary form `grow-[var(--ar)]`.
- `sizes` per item: `(min-width: 1400px) {round(1400 × share)}px, (min-width: 640px) {round(100 × share)}vw, 100vw`, where `share = ratio / Σratio` of its row. `widths` are capped at 1400 and at the stored width.
- Alt numbering continues across collection components (see ImageModule).
