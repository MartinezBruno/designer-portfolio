<decisions_applied>
- D-11a (CONTEXT, revised 2026-11-02): the side entrance replaces D-11's vertical drift. D-11's original text is kept there, marked superseded.
- Tokens (UI-SPEC "Motion Tokens" and "Detail-stack side entrance"): `--stack-travel: 7%` of the image's own width. The keyframe is `stack-enter` and the timeline is `--stack`, with `animation-range: entry 0% entry 100%` and `animation-timing-function: var(--ease-reveal)`. Why 7%: it is inside D-10's "about 5-10%" and under taste-skill motion.md "Keep the travel small (under 8% of the element)" for scroll-linked image moves. It is a one-way travel that ends at rest, so nothing is cropped once settled. It measures about 101 px for a full-bleed image at 1440, about 76 px for a padded image, and about 27 px at 390, which reads as "from the side" without becoming loud. `--ease-reveal` (the project's ease-out) follows motion.md §2 q3, "entering: ease-out". The taste review may lower the travel (not below 5%) or end the range earlier (not before `entry 60%`), and never the reverse.
- Alternation rule (Claude's discretion, recorded): it counts **eligible images only**, in page DOM order, starting at `left`, and **never resets** after a CollectionModule, text or embed. The eager image and opted-out images are not counted, so two neighbouring moving images never enter from the same side.
- Field naming: the overrides field is `stackMotion` (renamed from the old plan's `parallax`, because the detail stack no longer uses parallax). `false` opts out the whole project and a list of image ids opts out single images. Unknown ids are checked against `source.imageIds`, the same set moduleAlt uses.
- Attribute naming: frame `data-stack-frame`, image `data-stack-enter="left|right"`. These are deliberately **not** `data-parallax*`, so the 07-03 leak assertion "parallax animations == [data-parallax] elements" stays correct unchanged (stack images run `stack-enter`, never `parallax`). A parallel assertion is added for `stack-enter`.
- 07-08 lands `[data-parallax-frame='stack'] { --px-overscan: 3%; --px-travel: 2.6%; }` and its token-test assertions. No element uses them after this replan, so this plan removes that rule and those two assertions (UI-SPEC marks those values as superseded).
</decisions_applied>
