## Feature 1 — Hero portrait full width on phones

Source: D-01 to D-05 and sketch 001 (winning synthesis: C arch on D blue). Component: `src/components/sections/Hero.astro`.

### Geometry contract

| Breakpoint | Portrait width | Crop | Arch radius (on `<picture>`) |
|-----------|----------------|------|------------------------------|
| `<640px` (phones) [D-03] | **Full grid column** (`w-full`): 358px at 390px, 343px at 375px | **4:5** (`aspect-[4/5]`) [D-01] | `rounded-[50%_50%_1.25rem_1.25rem/40%_40%_1.25rem_1.25rem]` |
| `sm` (≥640px) | `sm:w-44` (176px) [D-03, unchanged] | 3:4 (`sm:aspect-[3/4]`) | `sm:rounded-[50%_50%_1.25rem_1.25rem/37.5%_37.5%_1.25rem_1.25rem]` (today's value) |
| `lg` (≥1024px) | `lg:w-64` (256px) [unchanged] | 3:4 | as `sm` |
| ≥87.5rem (1400px) | `min-[87.5rem]:w-[19rem]` (304px) [unchanged] | 3:4 | as `sm` |

**Why 40% at 4:5.** The top must stay a true semicircle. A semicircle needs a vertical radius of half the width. At 3:4 that is 0.5 × 3/4 = 37.5% of the height (today's value). At 4:5 it is 0.5 × 4/5 = **40%** of the height. If the phone keeps 37.5%, the top becomes a flattened ellipse, which breaks the sketch-001 arch.

- Bottom corners stay at 1.25rem, matching the 4:5 work cards. [D-01]
- Object position stays `object-[50%_6%]`. A 3:4 source in a 4:5 frame loses about 6% of its height, and with a 6% vertical anchor almost all of that comes off the bottom. The head and hair are not cropped.
- Order stays `order-first` on phones, so the portrait is above the headline. [D-02]
- `width={600} height={800}` stay as the intrinsic size attributes (the 3:4 source ratio). CSS `aspect-ratio` sets the rendered box, so CLS stays 0. [Existing pattern]

- The chip row is **left-aligned on the same left edge as the h1, the intro and the grid**. It sits 48px below the intro and 32px above the first row, so by proximity it belongs to the grid. [Claude's discretion] Reason: taste-skill laws ("text blocks share two or three left edges"; "gap between groups larger than gap within").
- The chips are **below** the intro, never above the heading. Chips above the h1 would be the banned pill-above-headline pattern.
- The chips wrap (`flex flex-wrap gap-2`) on every width. There is no horizontal scroller and no sticky bar. [Claude's discretion] Reason: there are only 5 chips, so wrapping keeps every option visible on phones, and a sticky bar would add chrome the house rules ban. At 390px, expect 2 to 3 lines.

### When the chip row renders

| Condition | Renders? |
|-----------|----------|
| 0 projects (existing empty state) | No |
| Fewer than 2 categories with ≥1 project | No [Claude's discretion]. Reason: a filter with one real option filters nothing. |
| 2 or more categories with ≥1 project (today: 4) | Yes. Chips are "All" plus each non-empty category in services.json `order` [D-12, D-13] |
| JS has not run (`html[data-motion]` not `on`/`reduced`) | The fieldset is in the HTML but hidden: `hidden motion-js:flex` (or the equivalent `motion-js:` display rule on the fieldset). All projects show. [D-14] |

Reason for using the `motion-js` variant: BaseLayout's blocking inline gate sets `html[data-motion]` before first paint [Existing], so the chips appear with **no layout shift** and there is never a dead control without JS. [Inference] In the rare `off` state (no `matchMedia`) the chips stay hidden and all projects show, which is acceptable.

Today's chips, in this order [D-13]: **All · Graphic design · Web design · Branding · Social media** (ES: **Todos · Diseño gráfico · Diseño web · Branding · Social media**).

### Chip component contract

**Semantics: a native radio group, the same as ServiceChips.** [Claude's discretion] Reason: single-select is radio semantics, and native radios give one tab stop, arrow-key movement and the checked state for free, without a hand-rolled roving tabindex.

```
<fieldset class="m-0 min-w-0 border-0 p-0" data-project-filter>
  <legend class="sr-only">{projects.filter.legend}</legend>
  <div class="flex flex-wrap gap-2">
    <div>
      <input type="radio" name="category" id="projects-filter-all" value="" checked class="peer sr-only" />
      <label for="projects-filter-all" class={chip}>{projects.filter.all}</label>
    </div>
    … one per non-empty category: id="projects-filter-{categoryId}", value="{categoryId}"
  </div>
</fieldset>
```

**Chip class:** the ServiceChips string **without the check icon**:
`inline-flex min-h-11 items-center rounded-full border-2 border-ink-muted px-4 py-2 text-sm font-semibold text-ink cursor-pointer hover:border-ink peer-checked:border-ink peer-checked:bg-ink peer-checked:text-surface peer-focus-visible:outline-2 peer-focus-visible:outline-offset-2 peer-focus-visible:outline-accent motion-on:transition-colors motion-on:duration-150`
- Keep the `// taste-skill-ignore: 2px radio-chip boundary (WCAG 1.4.11), not a 1px box` comment, as in ServiceChips.
- **No check icon.** [Claude's discretion] Reason: in ServiceChips the icon appears on check and widens the chip. In a filter that users arrow through, that makes the whole row reflow on every keypress. The ink fill is a strong luminance change, not hue alone, so WCAG 1.4.1 is still met, and `checked` carries the state to assistive tech.
- Use `motion-on:` rather than `motion-safe:` for the colour transition. The project rule is that new motion never uses `motion-safe:`, because `motion-safe:` ignores the header toggle. [Existing rule, global.css comment]
- Extract the shared chip base string into one module (for example `src/lib/ui/chip.ts`) so ServiceChips and the filter cannot drift apart. [Claude's discretion; the planner may decide to keep two literals if Tailwind's source detection makes the shared module awkward.]

### Interaction contract

| Input | Result |
|-------|--------|
| Tab into the group | Focus lands on the checked chip (one tab stop) [native] |
| Arrow keys | Move to the next or previous chip, check it and filter immediately (automatic activation, like tabs) [native radio] |

### URL contract (D-14)

- Param: `?category=<categoryId>`. The ids are the stable English ids in both locales (`/es/projects/?category=web-design`), the same as `?service=`.
- Selecting "All" **removes** the param, giving a clean `/projects/`.
- Every other search param and the hash are kept.
- **History: `history.replaceState(history.state, '', url)`**, not `pushState`. [Claude's discretion] Reasons: (1) arrow keys check a chip on every keypress, so pushState would add one history entry per keypress; (2) `<ClientRouter />` owns `popstate` and keys its entries on `history.state`. The project already uses `replaceState(view.history.state, …)` in `nav-focus.ts:252` for the same reason. **Back/forward behaviour that holds:** leaving /projects/?category=web-design for a project page and pressing Back restores the filtered list, because init reads the URL on `astro:page-load`. **The orchestrator should confirm this reading of D-14 ("works with back/forward") with the user.** If the user wants each chip change to be its own history entry, the planner must first verify how `pushState` interacts with Astro 7 ClientRouter's `popstate` handler. [Planner verifies]
- Parse with an allow-list: the ids of chips actually rendered. An unknown, empty, repeated or Photography-while-empty value falls back to All, silently (no announcement, and the URL is rewritten without the param). [D-14] Model the parser on `src/lib/contact/service-param.ts`.

### Filtering and grid rhythm

- Hidden cards get the `hidden` attribute on their `<li>`. They leave the layout, the tab order and the accessibility tree. DOM order stays newest first. [Existing D-18]
- **The rhythm is recomputed over the visible set.** `tileSize(index, visibleCount)` from `src/lib/projects/layout.ts` runs for each visible card, so a filtered list is laid out as if it were the whole list:
  - All (7): large, small, small, large, large, small, large-end (today's layout)
  - Web design (3): large, small, large-end
  - Graphic design (2): large, small
  - Branding (1) or Social media (1): large
- **Implementation constraint:** tile size must be switchable at runtime without generating new Tailwind classes. Use `data-tile="{size}"` on the `<li>` and on the cover frame, with literal variant classes covering all four sizes (for example `md:data-[tile=large]:col-span-7`, `data-[tile=small]:md:aspect-[7/8]`). Move the `sizesFor` map into `src/lib/projects/layout.ts` so the server render and the client script share one source, and update each visible image's `sizes` when its tile changes. [Claude's discretion] The Home "Latest work" row (`layout="row"`, `third`) is unaffected.
- The eager first cover (LCP on unfiltered /projects/) stays the SSR first card. A filtered deep link may make a lazy cover the first visible one. That is acceptable, and the LCP budget is measured on the unfiltered page only. [Claude's discretion]

### Live region (D-14)

- One `<p role="status" class="sr-only" data-project-filter-status>`, empty in the HTML.
- It is written **only after a user-initiated change**. It is never written on page load, including a deep link with `?category`. [Claude's discretion] Reason: a load-time announcement would compete with the page title announced by ClientRouter.

### Filter motion

[Claude's discretion]. The values come from the existing motion tokens; there is no new token.

| `html[data-motion]` | Behaviour on chip change |
|----------------------|--------------------------|
| `on` | **Out:** the cards that are leaving fade `opacity 1→0` over `--t-ui` (240ms, `--ease-soft`). Then the swap happens in one frame: set `hidden`, recompute `data-tile`. **In:** the visible cards rise `translate 0 16px → 0` with `opacity 0→1` over `--t-settle` (560ms, `--ease-reveal`), staggered 60ms per card and capped at 4 steps (the same cap as `reveal.ts`). Transform and opacity only. |
| `reduced` | **Instant.** Swap in one frame with no fade (CONTEXT: "must degrade to an instant change under reduced motion"). |
| `off` / no JS | Not reachable (the chips are hidden). |

Rules:
- **No FLIP or layout animation** of tiles changing size. Animated resizing of images is janky and expensive. The in/out fade carries the change.
- **Interruption:** a new selection during a transition cancels it and applies the new state from that frame (out-phase skipped, in-phase starts). No queued transitions.
- **Reveal interplay:** before the in-phase, mark every newly visible card's reveal targets as revealed instantly (`data-revealed` plus `data-reveal-instant`, or the reveal module's API if it exposes one). That way the scroll-reveal shutter never plays a second time on top of the filter entrance, and no card can stay hidden. [Planner verifies against `src/lib/motion/reveal.ts`]
- **Lifecycle (D-15):** register through `lifecycle.register(...)`. Init on `astro:page-load`; on `astro:before-swap` remove listeners, cancel running animations and timers, and leave no inline styles behind. After a swap, call `ScrollTrigger.refresh()` **only if GSAP is already loaded** (never import it for this). [Inference] Lenis auto-resizes on content height changes; the planner confirms. The card parallax uses a CSS view timeline [Existing comment in ProjectCard], so it needs no refresh.
- **Bundle:** the filter script must stay small and must not import GSAP. It is CSS transitions plus a few attribute writes. The largest eager script must stay under the 22,000 B budget (now 17,958 B, 08-18). Load it only on the Projects page.
