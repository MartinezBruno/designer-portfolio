<objective>
Fold the code-review advisory WR-01 into the gap set as a small, separable slice: under `on`, the anchor hook keeps `html.style.scrollBehavior = 'smooth'` until the glide lands (up to 1200 ms). The router's own `popstate` listener runs before ours, so a Back press during that window calls `scrollTo` while `smooth` is still set and the history restore glides. Fix: restore the inline value as soon as the glide has started.

Mechanism (decided): restore on the FIRST `scroll` event after the click (the glide has started; per the review, changing `scroll-behavior` does not stop an in-progress smooth scroll), with the existing restore-on-landing / restore-on-cancel as the fallback when no scroll happens. This is preferred over the review's single requestAnimationFrame, because the router may start the fragment scroll later than the first frame [Inference: router.js navigation is promise-based], and a too-early restore would kill the glide.

Purpose: MOTN-06 anchors and history must not produce motion the visitor did not ask for.
Output: nav-focus.ts change, unit tests, and an e2e regression test only if the bug reproduces in Chromium (verifier instruction).

Ordering: this plan runs in gap-closure wave 3, after 07-18 (wave 1) and 07-19 (wave 2), because it runs `pnpm build` and Playwright and neither may overlap another plan's build or e2e run on the shared `dist` and port 4400. 07-18 is reached transitively through 07-19. No worktree isolation is assumed.
