# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** four new static homepage blocks added to the Phase 1 skeleton: the availability badge (HOME-07), the roles marquee with its pause control (HOME-02, HOME-03), the 4 featured services (HOME-04), and the tools row (HOME-05), in EN at `/` and ES at `/es/`. Out of scope: latest Behance projects (HOME-06, Phase 3), service cards linking to contact (HOME-08, Phase 5), GSAP/Lenis/reveals/motion toggle (Phases 6–7).

**Inheritance:** everything in `01-UI-SPEC.md` (approved 2026-10-16) still applies: tokens, focus ring, 44px touch targets, typography sizes and weights, the copy rules, and the "no content hidden by `data-motion`" rule. **Amended by this phase:** the accent value (D-15) and the exhaustive accent list (D-16, D-17). Where this document doesn't mention something, Phase 1 governs.

**This revision merges `02-CONTEXT.md` (discuss-phase, 2026-10-16), which ran after the first version of this spec was approved. CONTEXT wins on every conflict.** Decisions are cited as `[CONTEXT D-nn]`.

**Provenance labels used below:**
- `[CONTEXT D-nn]`: locked user decision in `02-CONTEXT.md`.
- `[Upstream]`: decided in PROJECT.md, REQUIREMENTS.md, ROADMAP.md, research/*.md, 01-UI-SPEC.md, or 02-RESEARCH.md. Source is cited.
- `[Codebase]`: read from the implemented Phase 1 code on 2026-10-16.
- `[Verified]`: computed or checked on 2026-10-16 (contrast via the WCAG 2.x relative-luminance formula; icon files checked in `node_modules/@tabler/icons/icons/outline/`).
- `[Default]`: researcher choice inside a CONTEXT "Claude's Discretion" area, or where nothing upstream decides.
- `[Inference]`: logical deduction, not measured. Each one names how it gets verified.

**Visual hierarchy.** Primary focal point: the hero `<h1>` (her name, 48px display) and the portrait, unchanged from Phase 1. Secondary anchor: the full-bleed blue roles band directly below the hero, the only saturated block on the page. Everything after the band (services, tools) is quiet: surface tones and ink only.

## Spacing Scale

Same scale as Phase 1. Tailwind's default 4px utilities, no new spacing tokens.

| Token | Value | Tailwind | Usage (Phase 2) |
|-------|-------|----------|-----------------|
| xs | 4px | `1` | Gap between service bullets (`space-y-1`); tooltip vertical padding (`py-1`) |
| sm | 8px | `2` | Badge dot-to-text gap; tools row gap below 640px (`gap-2`); tile inner padding around the 32px icon; marquee wrapped row gap (`gap-y-2`); tooltip horizontal padding (`px-2`) and its 8px hover bridge (`pb-2`) |
| md | 16px | `4` | Badge horizontal padding; service card stack gap; tools row gap from 640px (`sm:gap-4`); gap between marquee track and pause button |
| lg | 24px | `6` | Service card padding; services grid gap; separator-to-role gap in the marquee (`gap-6`); bullet list indent (`pl-6`) |
| xl | 32px | `8` | Section heading (h2) to content gap; marquee band vertical padding (`py-8`); `--marquee-gap` between roles (2rem) |
| 2xl | 48px | `12` | Service icon chip diameter; **tool tile size** (`size-12`) |
| 3xl | 64px | `16` | Vertical padding of the content-sections wrapper and gap between content sections (`py-16 gap-16`) |

Exceptions:
- **Pause button: 44×44px minimum** (`min-h-11 min-w-11`), same touch-target rule as Phase 1 `[Upstream: 01-UI-SPEC]`.
- **Tool tiles: 48×48px** (`size-12`), above the 44px target. Five tiles plus four 8px gaps = 272px, which fits the 288px content width at 320px on one row `[Verified: arithmetic, 320 − 2×16 = 288]`.
- **Badge status dot: 8px** (`size-2`).
- Focus outline offset 2px (inherited, not a layout value).
- Content max width `max-w-6xl` and side padding `px-4 sm:px-6 lg:px-8` are the same as the hero `[Codebase: Hero.astro]`. The marquee band is the one full-bleed block (edge to edge, no `max-w`).
- Removed: the previous 56px `min-h-14` tool tile rule (it existed only for text-only tiles) `[CONTEXT D-12, D-14]`.

No new sizes or weights. Phase 1 reset `--text-*: initial`, and only `text-sm/base/2xl/5xl` compile. Any other size utility silently produces no CSS `[Codebase: global.css; Upstream: 02-RESEARCH Pitfall 9]`.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|

| Body | 16px (`text-base`) | 400 (600 for card titles only) | 1.5 | Inter |
| Heading | 24px (`text-2xl`) | 600 for section h2s; 400 elsewhere (Phase 1 hero title, footer h2) | 1.3 | Bricolage Grotesque |
| Display | 48px (`text-5xl`) | 600 | 1.1 | Bricolage Grotesque |

Weights in use: **400 and 600 only** (`font-semibold`, never `font-bold`).

### Phase 2 usage map

| Element | Tag | Role | Classes (contract) |
|---------|-----|------|--------------------|
| Availability badge text | `<p>` | Label, sentence case | `text-sm font-semibold text-ink` |
| Roles section heading | `<h2 class="sr-only">` | n/a (visually hidden) | `sr-only` |
| Role items, motion on (single animated line) | `<li>` | Display | `font-display text-5xl font-semibold tracking-tight text-accent-ink` |
| Role items, motion off (static wrapped list) | `<li>` | Heading | `font-display text-2xl font-semibold text-accent-ink` |
| Services and Tools section headings | `<h2>` | Heading 600 | `font-display text-2xl font-semibold tracking-tight` |
| Service card title | `<h3>` | Body 600 | `text-base font-semibold text-ink` |
| Service card bullet | `<li>` | Body 400 | `text-base text-ink-muted` |
| Tool tooltip text | `<span>` | Label, brand name as written | `text-sm font-semibold text-surface` |

Rules:
- **Roles change size with the motion gate:** `text-2xl motion-on:text-5xl`. With motion on, the roles run on one non-wrapping line at 48px. With motion off, the same roles wrap into a static list at 24px, which keeps it compact at 320px `[Default]`.
- Heading hierarchy: one `<h1>` (hero, unchanged), then `<h2>` per new section (Roles visually hidden, Services, Tools), then `<h3>` per service card. No `<h3>` for tools.
- Spanish runs about 15–25% longer `[Upstream: 02-RESEARCH Pitfall 10]`. Card titles, bullets, and the badge wrap. No `truncate`, no fixed heights, no `line-clamp`. Tooltips are `whitespace-nowrap` (brand names are short and untranslated).

Token changes in `@theme` (`src/styles/global.css`):
- `--color-accent: #0f70b7;` (replaces `#4b2ee8`, a single token swap that recolors the hero CTA, 404 CTA, focus rings, and footer link underline site-wide) `[CONTEXT D-15]`
- `--color-success: #1f7a4d;` (placeholder; brand palette beyond the primary is still pending Martina) `[Default; CONTEXT Deferred]`
- The Phase 1 axe and e2e suites are re-run after the swap `[CONTEXT D-15]`.

**Accent reserved for (exhaustive; Phase 1 list plus one Phase 2 entry):**
1. Hero primary CTA background
2. 404 primary CTA background
3. `:focus-visible` outline on every focusable element **on light surfaces** (now includes the 5 tool tiles). **Exception:** focusable elements inside the blue band use a white (`accent-ink`) outline instead, because accent on accent is 1:1 `[CONTEXT D-17]`
4. Footer text-link hover/focus underline
5. **Marquee band background** (full-bleed `bg-accent`) `[CONTEXT D-16]`

Not accent: the badge (dot or text), service icons, chips and bullets, tool icons and tiles, tooltips, section headings. The pause button never uses accent as its own fill or icon color.

**60/30/10 split, with a user-locked exception.** On a full scroll of the homepage, surface and surface-alt dominate and accent stays small (CTA, focus rings, one underline). The full-bleed band is a deliberate exception chosen by the client: on the first viewport below the hero it can read as more than 10% `[CONTEXT D-16]`. To keep it from tipping the balance, the band is the **only** accent-filled block on the page. No other section, card, or tile gets an accent background in this phase. Removed from the previous draft: the rule "marquee band is `surface-alt`, never an inverted band" and its ink-band rationale (superseded by D-16).

### Availability badge (`AvailabilityBadge.astro`): HOME-07

- **Placement:** inside the Hero text column, as the **first** child, above the greeting. It uses the existing 24px stack gap `[CONTEXT D-11]`.
- **Renders only when `available: true`.** When `profile.json` has `availability.available: false`, the component renders **nothing** (no element, no placeholder, no reserved space) `[CONTEXT D-08]`. Initial value: `available: true` `[CONTEXT D-09]`.
- **Markup (open state, the only state):** `<p class="inline-flex items-center gap-2 self-start rounded-full bg-surface-alt px-4 py-2 text-sm font-semibold text-ink">`, with a decorative dot `<span aria-hidden="true" class="size-2 rounded-full bg-success">` followed by `t('availability.open')`.
- **Data:** `src/data/profile.json` → `{ "availability": { "available": true } }`. Flipping the boolean and rebuilding shows or hides the badge with no code change (SC3 as amended) `[CONTEXT D-08]`.
- Removed from the previous draft: the closed state, the hollow-ring dot, and the `availability.closed` key `[CONTEXT D-08]`.
- **No motion:** no pulse, no ping, no transition `[Upstream: 02-RESEARCH Pattern 7]`.
- **Not a live region, not interactive:** no `role="status"`, no `aria-live`, no link, no tab stop `[CONTEXT D-11]`.
- It must not delay or displace the h1/portrait LCP. Plain server-rendered text, no image, no JS `[Upstream: HOME-01]`.

### Roles marquee (`RolesMarquee.astro`): HOME-02, HOME-03

**Structure:**
```
<section aria-labelledby="roles-title" data-marquee class="group bg-accent text-accent-ink py-8 [--marquee-gap:2rem]">
  <h2 id="roles-title" class="sr-only">{roles.heading}</h2>
  <div class="flex items-center gap-4">
    <div class="min-w-0 flex-1 overflow-hidden"> ← track (clips; required for 320px)
      <div class="flex gap-[var(--marquee-gap)]">
        <ul> roles (copy A, the only one exposed to AT) </ul>
        <ul aria-hidden="true" class="hidden motion-on:flex"> roles (copy B, visual duplicate) </ul>
      </div>
    </div>
    <button data-marquee-toggle ...>  ← after the track in DOM; shown only when motion is on
  </div>
</section>
```
- **Band:** full-bleed `bg-accent` (`#0F70B7`) with `text-accent-ink` (white) role text, matching the client mockup `[CONTEXT D-16]`.
- Each `<li>`: `inline-flex items-center gap-6 font-display font-semibold text-accent-ink text-2xl motion-on:text-5xl motion-on:tracking-tight whitespace-nowrap`, containing the `asterisk` icon (`size-6 text-accent-ink/70`, `aria-hidden`, 3.38:1) and then the role text. The separator comes **before** each role, so it reads as a bullet in the static list and as a divider in the loop.
- Each `<ul>` (both copies): `flex shrink-0 min-w-full flex-wrap items-center justify-center gap-x-[var(--marquee-gap)] gap-y-2 px-4 sm:px-6 lg:px-8 motion-on:flex-nowrap motion-on:justify-around motion-on:px-0 motion-on:animate-marquee motion-reduce:animate-none group-hover:[animation-play-state:paused] group-data-paused:[animation-play-state:paused]`. Extracted into one class constant in the component, not duplicated by hand `[Upstream: AGENTS.md]`.
- **Roles: exactly the 4 from D-03, in order** (Web design, Branding, Social media manager, Graphic design).
- **Track fill with 4 roles (duplication strategy):** two copies only (A exposed, B `aria-hidden`), each with `min-w-full`. `min-w-full` makes every copy at least as wide as the track at any viewport, so the loop has no blank gap whatever the role count. When the roles are narrower than the track, `motion-on:justify-around` spreads the slack evenly between them. No third copy and no repeated items inside a copy `[Upstream: 02-RESEARCH Pattern 3, ryanmulligan.dev; CONTEXT Claude's Discretion]`. `[Inference]` At 48px, the 4 roles are roughly 1.6–1.8k px wide, so at 1920px and wider the spacing between roles grows beyond the 32px gap. This is accepted; verify visually at 1920 and 2560 during execution. The e2e check asserts copy A's width ≥ the track's width at 1280, 1920 and 2560.
- **Motion tokens** (add to `src/styles/global.css`) `[Upstream: 02-RESEARCH Pattern 2]`:
  - `@custom-variant motion-on (&:where([data-motion='on'], [data-motion='on'] *));`
  - `@theme { --animate-marquee: marquee 40s linear infinite; @keyframes marquee { to { transform: translateX(calc(-100% - var(--marquee-gap))); } } }`
  - **Loop duration: 40s per copy, linear, infinite, left-moving** `[CONTEXT Claude's Discretion: 40s stays]`.

**States:**

| Condition | `html[data-motion]` | What renders |
|-----------|---------------------|--------------|
| JS on, no reduced-motion preference | `on` | Copy B visible, both copies animate at 40s/loop, roles at 48px on one line, pause button visible |
| Pointer hovering the band (fine pointer only; `group-hover` compiles inside `@media (hover:hover)`) | `on` | Animation paused while hovered. A bonus, not the conformance mechanism |
| Pause button pressed | `on` | `aria-pressed="true"`, section gets `data-paused`, animation paused until pressed again |
| `prefers-reduced-motion: reduce` | `off` | One static wrapped, centered list at 24px on the blue band. No copy B, no animation, no button |
| JS disabled or failed | `off` | Same as reduced motion |
| OS reduced-motion switched on mid-session | stays `on` | `motion-reduce:animate-none` stops the animation as a backup. The button stays visible and keeps working |

- **Screen readers hear each role exactly once** (copy B is `aria-hidden`). The track contains no focusable elements `[Upstream: SC1]`.
- **No horizontal page overflow at 320px:** the track's `overflow-hidden` clips copy B and the oversized line, and the band is full-bleed with no extra width (`tests/e2e/layout.spec.ts` asserts `scrollWidth <= 320`) `[Upstream: 02-RESEARCH Pitfall 8]`.

**Pause button** (the WCAG 2.2.2 mechanism), styled for the blue band `[CONTEXT D-17; Claude's Discretion]`:
- `<button type="button" data-marquee-toggle aria-pressed="false" aria-label={t('roles.pause')}>`
- Classes: `hidden motion-on:inline-flex shrink-0 mr-4 sm:mr-6 lg:mr-8 min-h-11 min-w-11 items-center justify-center rounded-full border-2 border-accent-ink bg-transparent text-accent-ink hover:bg-accent-ink hover:text-ink motion-safe:transition-colors motion-safe:duration-150 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent-ink`
- Rest: transparent fill (the band shows through), 2px white border, white icon: 5.22:1 for both.
- Hover: white fill, ink icon (17.85:1). The fill against the band is 5.22:1.
- **Focus: 2px white outline, 2px offset** (5.22:1 against the band). The 2px offset leaves a blue gap between the white border and the white outline, so the ring reads as a separate ring. **Never `outline-accent` inside the band** (1:1) `[CONTEXT D-17]`.
- Icons: `player-pause` visible while playing (`group-data-paused:hidden`), `player-play` visible while paused (`hidden group-data-paused:block`). Both `size-5`, `aria-hidden`.
- **The label never changes.** State is carried by `aria-pressed` only (APG toggle-button pattern) `[Upstream: 02-RESEARCH Pattern 4]`.
- Behavior: `src/lib/motion/marquee.ts` `initMarqueeToggles(doc)`, registered through the Phase 1 lifecycle registry, with cleanup via `AbortController`.
- Pause state is not persisted. A reload starts playing again `[Default]`.

### Featured services (`FeaturedServices.astro` + `ServiceCard.astro`): HOME-04

- `<section aria-labelledby="services-title">` → `<h2 id="services-title">{services.heading}</h2>` → `<ul class="grid gap-6 sm:grid-cols-2 lg:grid-cols-4">` with exactly 4 `<li>`, each one `ServiceCard`.
- Grid: 1 column below 640px, 2 columns from 640px, 4 columns from 1024px. **Cards in a row stretch to equal height (grid default `align-items: stretch` plus `h-full` on the card).** Bullet counts differ (3–6), so the shorter cards get empty space at the bottom. No fixed heights, no `line-clamp` `[CONTEXT D-04]`.
- **Order:** 1 Graphic design, 2 Web design, 3 Branding, 4 Social media, from the `order` field `[CONTEXT D-05]`.
- **ServiceCard** (root element is the `<li>` itself; no `<article>`, no landmark): `flex h-full flex-col gap-4 rounded-2xl bg-surface-alt p-6`. The UI-SPEC card style stays (the mockup's white/black-border/shadow style is deferred) `[CONTEXT Claude's Discretion, Deferred]`.
  1. Icon chip: `grid size-12 place-items-center rounded-full bg-surface`, containing the `ServiceIcon` at `size-6 text-ink` (`aria-hidden`)
  2. Text stack `flex flex-col gap-2`:
     - `<h3 class="text-base font-semibold text-ink">` title
     - `<ul class="list-disc space-y-1 pl-6 text-base text-ink-muted marker:text-ink-muted">` with one `<li>` per item **[CONTEXT D-04]**. Real list semantics. The visible disc marker keeps list semantics in Safari/VoiceOver, which drops them when `list-style: none` is used `[Default; Based on patterns: known WebKit behavior, verify with the accessibility tree snapshot in e2e]`. `pl-6` gives wrapped lines a hanging indent. No dashes typed into the text.
- **Removed from the previous draft:** the description `<p>`, the "1–2 sentences / ~120 characters" rule `[CONTEXT D-04]`.
- **Must not look clickable** in Phase 2: no `<a>`, no `cursor-pointer`, no hover lift, shadow, scale or border change, no arrow icon `[Upstream: 02-RESEARCH Deferred]`. Phase 5 (HOME-08) adds affordances.
- Service `id`s are stable kebab-case (`graphic-design`, `web-design`, `branding`, `social-media`). Phase 5 keys the contact pre-selection on them `[CONTEXT D-05]`.
- Count is guarded: anything other than exactly 4 fails the build `[Upstream: 02-RESEARCH Pattern 5]`.

### Tools row (`ToolsRow.astro` + `ToolIcon.astro` + `src/lib/ui/tooltips.ts`): HOME-05

**Icon-only tiles with a tooltip** `[CONTEXT D-12, D-13, D-14]`.

- `<section aria-labelledby="tools-title">` → `<h2 id="tools-title">{tools.heading}</h2>` → `<ul class="flex flex-wrap gap-2 sm:gap-4">` (start-aligned, like the heading). Exactly the 5 tools of D-12, in mockup order: Adobe Illustrator, Adobe InDesign, Adobe Photoshop, Figma, Adobe Lightroom.
- **Tile markup** (one per `<li class="relative">`):
  ```
  <span role="img" tabindex="0" aria-labelledby="tool-{id}-name" data-tool
        class="group/tool relative grid size-12 place-items-center rounded-2xl border border-ink/10 bg-surface text-ink
               focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent">
    <ToolIcon name={icon} />                                     ← size-8, aria-hidden, focusable="false"
    <span id="tool-{id}-name" class="sr-only">{name}</span>        ← the accessible name (always present)
    <span aria-hidden="true" data-tooltip class="{tooltip classes}"> ← visual-only tooltip
      <span class="block whitespace-nowrap rounded-lg bg-ink px-2 py-1 text-sm font-semibold text-surface">{name}</span>
    </span>
  </span>
  ```
- **Semantics decision: name as label, tooltip visual-only.** The tile is a focusable `role="img"` whose accessible name comes from `aria-labelledby` → the sr-only span. The tooltip is `aria-hidden="true"`. Rationale:
  - The tooltip text is identical to the name. `aria-describedby` → `role="tooltip"` would make screen readers announce "Figma, image, Figma". Name-as-label announces it once.
  - `role="img"` makes the children presentational and gives the element a role that supports a name. A bare `<span tabindex="0">` (generic role) cannot be named. A `<button>` would announce an action that doesn't exist.
  - The sr-only name works with JS off and with the tooltip hidden, as D-14 requires ("must not be the only label").
- **Tooltip visual:** ink fill, surface text (16.70:1), `rounded-lg`, `px-2 py-1`, `text-sm font-semibold`, **no arrow**, positioned **above** the tile with an 8px gap. No accent anywhere in the tooltip `[CONTEXT D-14]`.
- **Tooltip classes:** `pointer-events-auto absolute bottom-full z-10 pb-2 invisible opacity-0 group-hover/tool:visible group-hover/tool:opacity-100 group-focus-visible/tool:visible group-focus-visible/tool:opacity-100 group-data-open/tool:visible group-data-open/tool:opacity-100 group-data-dismissed/tool:invisible! group-data-dismissed/tool:opacity-0! motion-safe:transition-[opacity,visibility] motion-safe:duration-150`, plus the horizontal anchor below.
  - The 8px gap is **padding** (`pb-2`) on the transparent wrapper, not margin. The pointer can therefore travel from the tile onto the tooltip without leaving the hover area (WCAG 1.4.13 "hoverable").
  - `!` (important) on the dismissed variant so Esc beats hover and focus regardless of CSS order. `[Inference]` Tailwind 4 emits these as `!important`; verify the compiled CSS during execution.
- **Horizontal anchor (prevents overflow at 320px):** index 0 → `left-0` (start-aligned); last index → `right-0` (end-aligned); every other tile → `left-1/2 -translate-x-1/2` (centered). The component derives this from the item index, not from content. `[Inference]` At 320px a centered "Adobe Illustrator" tooltip on the first tile would extend about 36px past the left edge, hence the start anchor. The e2e layout test shows each tooltip (focus every tile in turn) at 320px and asserts `scrollWidth <= 320`.
- **Show / hide rules (WCAG 1.4.13)** `[CONTEXT D-14]`:

  | Trigger | Result |
  |---------|--------|
  | Pointer hover (fine pointer) | Shows; stays while the pointer is over the tile or the tooltip (hoverable) |
  | Keyboard focus (`:focus-visible`) | Shows; stays until blur or Esc (persistent) |
  | Tap (touch/pen) | Toggles `data-open` on the tile; a second tap on it closes it |
  | Tap anywhere outside a tile | Removes `data-open` from all tiles |
  | Esc | Sets `data-dismissed` on every visible tile (dismissible without moving pointer or focus) |
  | Showing one tile | Removes `data-open` from, and sets `data-dismissed` on, every other tile (only one tooltip at a time) |
  | Fresh `pointerenter` or `focusin` on a tile | Clears that tile's `data-dismissed` |

- **Script:** `src/lib/ui/tooltips.ts` `initToolTooltips(doc)`, a pure DOM function like `initMarqueeToggles`, registered through the Phase 1 lifecycle registry with `AbortController` cleanup. It touches only `data-open` and `data-dismissed` `[CONTEXT D-14]`. `[Proposed]` The folder is `lib/ui` because tooltips are not motion; the planner may co-locate it with `lib/motion/marquee.ts` if that's simpler.
- **JS off:** the CSS `group-hover`/`group-focus-visible` variants still show the tooltip. Tap-to-show and Esc need JS. The sr-only name serves AT either way.
- **Motion:** opacity fade only, `motion-safe:` only. No slide, no scale.
- Brand icons inherit `currentColor` (`text-ink`). They are never recolored with brand colors or accent `[Upstream: FEATURES.md]`.
- Tool names are brand names and are **not translated**. Same strings on `/` and `/es/` `[CONTEXT D-12]`.
- No links to vendor sites, no skill bars, percentages or ratings. No second marquee `[Upstream: FEATURES.md]`.
- Count is guarded: an empty list fails the build (`assertNonEmpty`).
