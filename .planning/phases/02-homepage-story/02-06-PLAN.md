<semantics_decision>
Chosen (UI-SPEC "Semantics decision", D-14 asks for it): name-as-label, tooltip visual-only. The tile is `<span role="img" tabindex="0" aria-labelledby="tool-{id}-name" data-tool>`; the name lives in a child `<span id="tool-{id}-name" class="sr-only">`; the tooltip is a sibling child with `aria-hidden="true"`. Rejected: aria-describedby → role="tooltip" (announces "Figma, image, Figma"); `<button>` (announces a non-existent action); bare `<span tabindex>` (generic role cannot be named).

Lint decision (PATTERNS flag 1): `jsx-a11y-x/no-noninteractive-tabindex` is `error` in the strict preset with default options `{ roles: [], tags: [] }` and supports a `roles` allow-list (verified in node_modules/eslint-plugin-jsx-a11y-x/lib/rules/no-noninteractive-tabindex.js). Use a FILE-SCOPED override in eslint.config.js for `src/components/sections/ToolsRow.astro` only, setting `['error', { roles: ['img'], tags: [] }]`, with a comment citing D-14. Rejected: a global override (would allow focusable images everywhere) and inline disable comments (less discoverable in Astro templates). The rule stays fully strict for every other file.
</semantics_decision>
