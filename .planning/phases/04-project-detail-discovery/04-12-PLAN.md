## Phase Goal

ROADMAP Phase 4 goal (verbatim): "A visitor can open any project and see its full Behance content styled inside the site, with context and navigation. If the catalog is big enough, they can also narrow the Projects list by category, tool, year, or text."

Gap being closed (04-VERIFICATION.md `known_gaps`, 04-11-SUMMARY.md "Open Gaps"): "PNG `<Picture>` fallbacks weigh 205 MB of the 244 MB dist." User verdict in 04-11: **"Gap plan: webp fallback (Recommended)"**.

<objective>
Stop Astro's `<Picture>` from emitting PNG fallbacks. Every call site switches to an AVIF `<source>` plus a WebP `<img>` fallback, driven by one shared constant. The plan measures dist size and cold build time before and after on the same machine.

Purpose: 04-11 measured 457 PNG files / 205 MB of the 244 MB dist and a 72.6 s cold build. Astro's `Picture.astro` defaults `fallbackFormat` to `png` for PNG/WebP sources (`defaultFallbackFormat = 'png'`; only gif/svg/jpg/jpeg sources keep their own format). Module images are committed WebP and the hero portrait is PNG, so all of them got PNG fallbacks at every width.
Output: `src/lib/ui/picture-format.ts`, 6 updated call sites, a unit guard test, an updated hero e2e, and a SUMMARY with the before/after measurement table.
</objective>

<format_decision>
[Proposed] Decision, based on evidence:

1. **Fallback = WebP, not JPG.** The user chose WebP. Evidence from 04-11: the 457 WebP outputs at the same widths totaled 23.7 MB, against 205 MB for PNG. JPG has no alpha channel. The hero portrait is a PNG drawn as `rounded-full object-contain`, so `[Inference]` it may rely on transparency, and a JPG would flatten it onto a solid background. WebP keeps alpha.
2. **`formats: ['avif']` plus `fallbackFormat: 'webp'`, not `['avif','webp']` plus `fallbackFormat: 'webp'`.** In `node_modules/astro/components/Picture.astro`, each entry in `formats` becomes a `<source>`, and the fallback is a separate `getImage` call that renders as the `<img>`. If WebP stayed in `formats`, the markup would have a redundant WebP `<source>` that duplicates the `<img>` srcset. Removing it would also depend on unverified same-hash dedup between the two `getImage` calls. With `['avif']`, WebP is encoded once per width, as the `<img>`. Because the WebP widths match the old WebP `<source>` widths, `[Inference]` the WebP file count should match the baseline.
3. **Browser support.** `[Documented: caniuse webp]` WebP in `<img>` works in all evergreen browsers: Chrome 32+, Firefox 65+, Edge 18+, and Safari 14+ on macOS 11+ and iOS 14+. AVIF-capable browsers keep loading the AVIF `<source>`, so most visitors see the same pixels as before. Only pre-2020 browsers without WebP lose the image, and they are outside the project's evergreen target `[Assumption: no legacy-browser requirement in REQUIREMENTS.md]`.
4. **Shared constant, not a wrapper component.** There are 6 call sites in 5 files, and they must stay identical. Repeating two props six times invites drift, which the old repeated `formats={['avif', 'webp']}` already shows. A wrapper component would be a premature abstraction (AGENTS.md), so the shared piece is a single exported object spread onto `<Picture>`.
5. **The OG image (`getImage(... format: 'jpg')` in both `[slug].astro` pages) does not change.** It is 7 files / 0.6 MB, and JPG is required for crawler support.
</format_decision>
