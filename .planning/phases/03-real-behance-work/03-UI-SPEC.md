# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this contract covers:** the visitor-facing parts of Phase 3, in EN and ES:
- the Home "Latest work" section (HOME-06 as amended by D-17)
- the Projects list page at `/projects/` and `/es/projects/` (PROJ-01)
- the `ProjectCard` component, in `compact` and `full` variants (D-19)
- the "Projects" link in the header nav, plus the header layout change it forces below 640px (D-20)

**Out of scope:**
- the sync CLI, snapshot, overrides and consent note. These have no visitor UI. Only their build-error copy appears here.
- detail pages (Phase 4)
- filters and search (N/A at 7 projects)
- any new motion (Phases 6–7)

**Inheritance:** `01-UI-SPEC.md` and `02-UI-SPEC.md` (both approved 2026-10-16) still apply where this document is silent. That covers tokens, the focus ring, 44px touch targets, the "no content hidden by `data-motion`" rule, the copy rules, and the rule of no string literals in components.

**Provenance labels:**
- `[CONTEXT D-nn]`: a locked decision in `03-CONTEXT.md`.
- `[Upstream]`: decided in 03-RESEARCH, earlier UI-SPECs, PROJECT/CLAUDE.md or AGENTS.md. The source is named.
- `[Codebase]`: read from `src/` on 2026-10-17.
- `[Verified]`: measured or computed on 2026-10-17. The method is named.
- `[Default]`: my choice, inside a CONTEXT "Claude's Discretion" area.
- `[Inference]`: deduced and not yet measured. Each one says how it will be checked.

**Taste skill:** CLAUDE.md requires `taste-skill` for this work. The skill's own special case "A component or a single section, not a page" applies: no new direction is drawn, the existing design is matched, and the house rules and laws are applied. Decisions below that come from the skill are tagged `[Taste: <rule>]`. The implemented result must still pass `lint.mjs` and `inspect.mjs` (see Verification).

**Visual hierarchy:**
- **Home:** the hero `<h1>` and portrait stay the main focal point. The new section's anchor is the **first, large cover** (7/12 columns). Its 7-column width makes it the only image below the hero bigger than the services cards.
- **Projects page:** the `<h1>` (48px) comes first, then the large covers in the zig-zag rhythm. Covers do the visual work. Text stays small and quiet.

## Spacing Scale

Same 4px-based Tailwind scale as Phases 1 and 2. No new spacing tokens.

| Token | Value | Tailwind | Usage (Phase 3) |
|-------|-------|----------|-----------------|
| xs | 4px | `1` | Row gap inside the card meta list (`gap-y-1`); dt-to-dd gap (`gap-1`) |
| sm | 8px | `2` | Card text stack gap (title → summary → meta, `gap-2`); "See all" text-to-icon gap (`gap-2`) |
| md | 16px | `4` | Cover-to-text gap inside a card (`gap-4`); column gap between meta items (`gap-x-4`) |
| lg | 24px | `6` | Grid column gap at md+ (`md:gap-x-6`); header nav link gap (`gap-6`); Projects page h1-to-intro gap (`gap-6`) |
| xl | 32px | `8` | Home section h2 → grid → "See all" stack (`gap-8`), the same rule as the other Home sections |
| 2xl | 48px | `12` | Row gap of the project grid at every width (`gap-y-12`); Projects page intro → grid (`gap-12`) |
| 3xl | 64px | `16` | Projects page vertical padding (`py-16`); the Home content-sections wrapper keeps its existing `gap-16 py-16` |

Exceptions:
- **Touch targets:** every link is at least 44px tall (`min-h-11`). Nav links, "See all" and the empty-state link meet this directly. A project card's link target is the whole tile (stretched link), which is far above 44px.
- **Grid row gap (48px) stays below the section gap (64px)**, so rows read as one section. `[Taste: section gap clearly larger than any gap inside]`
- **Scroll padding for the sticky header:** `<html>` gets `scroll-pt-24 sm:scroll-pt-20` (96px / 80px), so focused tiles and the `#contact` anchor are never hidden under the header (WCAG 2.4.11). These values match the measured header heights below. `[Inference]` Verify with an e2e check that Shift+Tab back to a tile leaves its top edge below the header's bottom edge.
- Page side padding and max width are the same as every other section: `mx-auto max-w-6xl px-4 sm:px-6 lg:px-8` `[Codebase]`.
- **Known, not changed here:** taste-skill asks for 120–220px between sections on desktop, and Home uses 64px. Retuning the Home rhythm site-wide belongs to a polish phase, not this one. It is recorded under Open Questions.

Rules:
- **Heading outline.**
  - Home: h1 (hero) → h2 sr-only "What I do" → h2 Services → h3 ×4 → **h2 "Latest work" → h3 ×(1–3)** → h2 Tools → h2 footer.
  - Projects: **h1 "Projects" → h2 per project** → h2 footer.
  - `ProjectCard` takes a `headingLevel: 2 | 3` prop. Compact uses 3 and full uses 2.
- **Two-line headlines** `[Taste: headlines two lines or fewer at every width]`. Project titles must fit in two lines inside the narrowest tile:
  - At 768px, a small tile is about 286px wide (24px titles).
  - At 320px, a stacked tile is 288px wide.
  - Title overrides (`title.en` and `title.es`) are therefore **at most 32 characters**. The overrides schema enforces this with `.max(32)`, so a longer title fails the build. `[Default; Upstream: taste copy.md "about 32 characters is safe"]`
- No `truncate`, no `line-clamp`, no fixed text heights. Spanish runs 15–25% longer and wraps naturally `[Upstream: 02-UI-SPEC]`.
- **Fallback titles keep the original language.** When a project has no title override for the page locale, the Behance title renders inside `<span lang={contentLang}>`. `contentLang` defaults to `es` and can be overridden. The `lang` attribute is omitted when `contentLang` equals the page locale. `[CONTEXT D-10; Upstream: 03-RESEARCH A2, Open Question 3]`
- Year is `<time datetime="YYYY">YYYY</time>`, computed in UTC `[Upstream: 03-RESEARCH Pattern 6]`.
- Category and tools are **never uppercased** and never letter-spaced `[Taste: no tiny uppercase letter-spaced labels]`.

### `ProjectGrid.astro`: the fixed-rhythm asymmetric grid (D-18)

**Container:** `<ul class="grid grid-cols-1 gap-y-12 md:grid-cols-12 md:gap-x-6">`. It uses grid-auto-flow `row` (the default). **Never `grid-flow-dense`, never `order-*`, never row-span.** As a result, DOM order, tab order and visual reading order are all newest first: top to bottom on mobile, and row by row, left to right from `md`. `[CONTEXT D-18; Upstream: 03-RESEARCH Pattern 7]`

**Tile size comes from position**, through a pure function `tileSize(index, count)` in `src/lib/projects/layout.ts`. It returns `'large' | 'small' | 'large-end'`, it is unit-tested, and it uses no CSS `nth-*` selectors.
- If `count > 1`, `count` is odd and `index === count - 1`, it returns **`large-end`**: a lone last tile pushed to the right edge.
- Otherwise it cycles by `index % 4`: `0 → large`, `1 → small`, `2 → small`, `3 → large`.

| Size | Tile (`<li>`) classes from `md` | Cover box aspect | Placement |
|------|---------------------------------|------------------|-----------|
| `large` | `md:col-span-7` | `aspect-[5/4]` | starts wherever it falls |
| `small` | `md:col-span-5` | `aspect-[5/4] md:aspect-[7/8]` | starts wherever it falls |
| `large-end` | `md:col-span-7 md:col-start-6` | `aspect-[5/4]` | right-aligned, ending at column 12 |

Below `md` every tile is full width with an `aspect-[5/4]` cover.

The class strings are literal maps in the component, so Tailwind can see them. `[Default; CONTEXT Claude's Discretion: exact rhythm]`

**The resulting rhythm** (L = large, S = small, E = large-end):

| Count | Rows from `md` |
|-------|----------------|
| 7 (Projects today) | `L S` · `S L` · `L S` · `· E` |
| 3 (Home) | `L S` · `· E` |
| 2 | `L S` |
| 1 | `L` (start-aligned) |
| 4 / 5 / 6 | `L S · S L` / adds `· E` / adds `L S` |

No combination leaves a hole mid-grid. The only empty space is the 5 columns to the left of a closing `E` tile, which ends the zig-zag on purpose.

**Why 5/4 and 7/8 share a row height** `[Verified: arithmetic, 12 columns, 24px gutters]`:
- At a 1088px content width (max-w-6xl minus 2×32px), 7 columns are 624.7px wide, so 5/4 → 499.7px tall. 5 columns are 439.3px wide, so 7/8 → 502.1px tall.
- At a 720px content width (768px viewport), 410px → 328px and 286px → 327px.

Covers in a row therefore line up within about 2px, and titles start on the same line without row-spans. Behance covers are about 1.28:1 (crop 1027×803):
- 5/4 crops almost nothing.
- 7/8 keeps about 68% of the cover's width, centred (`object-cover object-center`).

`[Inference]` Check the 7 real covers for cropped key text at 7/8 in the taste screenshots. If one crops badly, add an optional `coverPosition` override (`object-left`/`object-right`) in a fix plan. Do not change the aspect rhythm.

### `ProjectCard.astro`: one component, two variants (D-19)

Props: `project: ProjectCardView`, `variant: 'compact' | 'full'`, `headingLevel: 2 | 3`, `size` (from `tileSize`), `eager: boolean`.

**Structure.** There is no card box: no background, border, radius, shadow or padding. The cover and the text sit directly on the page surface. `[Taste: no rows of identical cards, no shadows at rest, no thin rules]`

```
<li class="{size classes}">
  <article class="relative flex flex-col gap-4">
    <div class="{aspect classes} overflow-hidden bg-surface-alt">          ← media box, square corners
      <Picture src={cover} alt={coverAlt} formats={['avif','webp']}
               widths={[404, 640, 808]} sizes={sizesFor(size)}
               loading={eager ? 'eager' : 'lazy'} fetchpriority={eager ? 'high' : undefined}
               decoding="async" class="size-full object-cover object-center" />
    </div>
    <div class="flex flex-col gap-2">
      <h{2|3} class="{title classes}">
        <a href={href} class="{link classes}">
          {titleLang ? <span lang={titleLang}>{title}</span> : title}
        </a>
      </h{2|3}>
      {variant === 'full' && summary && <p class="max-w-[60ch] text-base text-ink">{summary}</p>}
      <dl class="flex flex-wrap gap-x-4 gap-y-1 text-sm text-ink-muted">
        {category && <div class="flex gap-1"><dt class="sr-only">{t('projects.meta.category')}</dt><dd>{category}</dd></div>}
        <div class="flex gap-1"><dt class="sr-only">{t('projects.meta.year')}</dt><dd><time datetime={year}>{year}</time></dd></div>
        {variant === 'full' && tools.length > 0 &&
          <div class="flex basis-full gap-1"><dt class="sr-only">{t('projects.meta.tools')}</dt><dd>{tools.join(', ')}</dd></div>}
      </dl>
    </div>
  </article>
</li>
```

- **Square-cornered covers** (no `rounded-*`), unlike the rounded service cards. Covers are Martina's work, shown like plates in a gallery. Service cards are UI. `[Taste: media square unless the direction says otherwise]`
- **Stretched link, one tab stop per card:** the `<a>` carries `after:absolute after:inset-0 after:content-['']`, so the whole tile (cover + text) is clickable.
  - The link's accessible name is the title only. The cover keeps its own alt outside the link, so names are not duplicated. `[Upstream: 03-RESEARCH Pattern 6]`
  - **Focus ring on the whole tile:** `outline-hidden focus-visible:after:outline-2 focus-visible:after:outline-offset-4 focus-visible:after:outline-accent`. `outline-hidden` keeps a ring in forced-colors mode.
- **Link classes:** `text-ink decoration-accent decoration-2 underline-offset-4 group-hover/card:underline focus-visible:underline outline-hidden after:absolute after:inset-0 after:content-[''] focus-visible:after:outline-2 focus-visible:after:outline-offset-4 focus-visible:after:outline-accent`, with `group/card` on the `<article>`.
  - Hovering anywhere on the tile underlines the title. Nothing else changes.
  - Motion-driven hover (cover scale, reveal) is Phase 6.
- **Meta is plain text, not chips.** Category, year and tools are a `<dl>` with visually hidden `<dt>` labels:
  - Screen readers hear "Category, Web design; Year, 2025; Tools, Figma, Adobe Photoshop".
  - Sighted users see `Web design   2025` on one line, with tools on the next (full variant).
  - Category is never a pill and never colored. `[Taste: no pill badges]; [CONTEXT D-11, D-12]`
- **Without a category override** the category item is omitted, so only the year shows. **Without a summary** the summary line is omitted. With no tools, the tools line is omitted. No placeholder text and no reserved space. `[CONTEXT D-14, D-22]`
- **Compact (Home)** shows the cover, the title at `text-base font-semibold`, and category + year. **Full (Projects)** shows the cover, the title at `font-display text-2xl font-semibold tracking-tight`, the summary, category + year, and tools. All information is visible at rest. Nothing exists only on hover or focus. `[CONTEXT D-11, D-19]`
- **`sizesFor(size)`** (literal strings):
  - `large` / `large-end`: `(min-width: 1152px) 625px, (min-width: 768px) 57vw, 100vw`
  - `small`: `(min-width: 1152px) 440px, (min-width: 768px) 40vw, 100vw`

  Sources top out at 808px (D-21), so `widths` never exceeds 808. Astro never upscales. `[Inference]` Large tiles on 2× screens show the 808px source slightly soft. This is accepted for Phase 3. Phase 4's module images do not change covers.
- **Loading:**
  - Projects page: only tile 0 is `eager` + `fetchpriority="high"`, since it is the LCP candidate below the h1. All other tiles are `lazy`.
  - Home: all 3 are `lazy`, because they sit below the fold under the hero, marquee and services.
- **No layout shift:** the cover box has a fixed aspect ratio, and `<Picture>` receives intrinsic `width`/`height` from `ImageMetadata`. `[CONTEXT D-18]`
- **Detail links 404 until Phase 4** (accepted). The cards do not mark this, and there is no Behance link in the cards. `[CONTEXT D-09]`

## Accessibility Contract (Phase 3 acceptance)

- axe reports zero WCAG 2.2 AA violations on `/`, `/es/`, `/projects/` and `/es/projects/`, with motion on and with `reducedMotion: 'reduce'`.
